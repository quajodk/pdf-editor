### Technical Implementation Notes

**PDF Coordinate System:**
- Canvas: Origin at top-left, Y increases downward
- PDF: Origin at bottom-left, Y increases upward
- Conversion: `pdfY = pageHeight - canvasY - height`

**pdf-lib Rendering:**
- Text: `page.drawText()` with font embedding
- Rectangles: `page.drawRectangle()` with border
- Ellipses: `page.drawEllipse()` with center and radii
- Lines: `page.drawLine()` with start/end points
- Highlights: Rectangles with opacity
- Drawings: Series of connected `drawLine()` calls

**Limitations:**
- pdf-lib doesn't support arrow heads (drawn as regular lines)
- pdf-lib doesn't support smooth curves (pen strokes are segmented)
- Font embedding not yet implemented (uses default fonts)

```javascript
// Start with original order: [1, 2, 3]
const pageOrder = [1, 2, 3];

// Page 3 → position 2
```

```javascript
// For each annotation, find its new page number
const reorderedAnnotations = allAnnotations.map(ann => {

});
```

## Session 25: Text Editing Overlap Bug Fix
**Date**: January 28, 2026
**Duration**: ~1 hour

### Issue Reported
User reported a bug where editing text in the "Edit Text" feature caused overlapping with adjacent text. The problem was that text was extracted word-by-word, so when a short word (e.g., "Darboa") was edited to a longer phrase (e.g., "Darboa admission into"), it would overlap the following word.

Screenshot provided showed: "Darboaadmission into" with overlapping text.

### Root Cause Analysis
1. **Text Extraction**: Each word was extracted as a separate editable item with fixed boundaries
2. **Input Method**: Single-line input field constrained to original word width
3. **Fixed Boundaries**: Width and height were locked to original text dimensions
4. **No Expansion**: Edited text couldn't expand beyond original bounds

### Solution Implemented

#### 1. Text Grouping by Lines/Paragraphs (PDFEditor.tsx)
- Changed text extraction from word-level to line-level grouping
- Group text items by Y-coordinate (vertical position) with 5px tolerance
- Sort items within each line by X-coordinate (horizontal position)
- Combine all words in a line into a single editable block
- Calculate proper boundaries: min/max X and Y for the entire line

**Before**: Each word = separate editable area
**After**: Each line = single editable area

#### 2. Multi-line Textarea Input (PDFCanvas.tsx)
- Replaced single-line `<input>` with multi-line `<textarea>`
- Added Ctrl+Enter keyboard shortcut to save
- Textarea is resizable by default
- Added helper text: "Press Ctrl+Enter to save, Esc to cancel"
- Minimum size based on original text dimensions

#### 3. Dynamic Boundary Expansion (PDFCanvas.tsx)
- Calculate text width: `max(originalWidth, newTextLength * 0.6 * fontSize)`
- Calculate text height for multi-line: `lines.length * fontSize * 1.2`
- Line height multiplier of 1.2 for proper spacing
- Text boundaries expand automatically based on content

#### 4. Rendering Improvements (PDFCanvas.tsx)
- Text rendering uses `whiteSpace: 'pre-wrap'` for multi-line support
- Added `wordBreak: 'break-word'` to prevent overflow
- Set `maxWidth` to prevent excessive expansion
- Proper line height calculation (1.2x font size)

#### 5. PDF Export Updates (PDFEditor.tsx)
- Download function: Handle multi-line text by splitting on '\n'
- Print function: Same multi-line text handling
- Draw white rectangle to cover original text
- Draw each line separately with proper Y-offset
- Line spacing: `lineHeight = fontSize * 1.2`

### Code Changes

**Files Modified**:
1. `frontend/src/components/PDFEditor.tsx` (lines 69-140, 193-221, 463-489)
2. `frontend/src/components/PDFCanvas.tsx` (lines 433-455, 880-903, 950-984)

**Key Implementation Details**:

```javascript
// Text grouping algorithm
- Group items by Y-coordinate (±5px threshold)
- Sort lines by Y (top to bottom)
- Sort items in line by X (left to right)
- Combine into single text block per line

// Dynamic sizing
const charWidth = fontSize * 0.6;
const estimatedWidth = Math.max(originalWidth, newText.length * charWidth);
const lines = newText.split('\n');
const lineHeight = fontSize * 1.2;
const estimatedHeight = Math.max(originalHeight, lines.length * lineHeight);

// Multi-line rendering in PDF
lines.forEach((line, index) => {
  page.drawText(line, {
    x: textX,
    y: pageHeight - textY - (index * lineHeight),
    size: fontSize,
    color: rgb(r, g, b)
  });
});
```

- Added useEffect hook to attach window-level mousemove/mouseup listeners during resize
- Ensures resize completion is captured even when mouse moves outside canvas
- Properly calculates unscaled PDF coordinates from screen coordinates
- Cleans up event listeners when resize operation completes

**3. Coordinate System Handling**
- ExtractedTextItems store unscaled PDF coordinates
- ResizePreview maintains unscaled values during drag
- Display multiplies by scale factor for screen rendering
- Y-coordinate correctly accounts for text baseline vs top-left corner

```typescript
// Added interface method
updateExtractedTextItem: (id: string, updates: Partial<ExtractedTextItem>) => void;

// Implementation
updateExtractedTextItem: (id, updates) => set((state) => {
  const updatedText = state.extractedText.map(item =>
    item.id === id ? { ...item, ...updates } : item
  );
  return { extractedText: updatedText };
}),
```

**frontend/src/components/PDFCanvas.tsx:**

```typescript
useEffect(() => {
  if (!resizingTextBlock) return;

  const handleGlobalMouseMove = (e: MouseEvent) => {
    // Calculate new dimensions with proper scale division
    // Update resizePreview state for visual feedback
  };

  const handleGlobalMouseUp = () => {
    if (resizingTextBlock && resizePreview) {
      // Persist dimensions to store
      updateExtractedTextItem(resizingTextBlock.id, {
        x: resizePreview.x,
        y: resizePreview.y + resizePreview.height,
        width: resizePreview.width,
        height: resizePreview.height,

  };

  window.addEventListener('mouseup', handleGlobalMouseUp);

  return () => {
    window.removeEventListener('mousemove', handleGlobalMouseMove);
    window.removeEventListener('mouseup', handleGlobalMouseUp);
```

### Technical Notes

**Event Handling Pattern:**
The global event listener pattern is critical for drag operations:
- Local handlers (onMouseMove/onMouseUp on div) fail when mouse leaves element
- Window-level listeners ensure events are captured regardless of mouse position
- This pattern is common in drag-and-drop implementations
- Proper cleanup in useEffect return prevents memory leaks

**Coordinate Systems:**
Three coordinate systems at play:
1. Screen coordinates (clientX/clientY) - from mouse events
2. Canvas coordinates (relative to canvas div) - for positioning elements
3. PDF coordinates (unscaled) - stored in ExtractedTextItem

Conversions:
- Mouse → Canvas: subtract canvas.getBoundingClientRect() offset
- Canvas → PDF: divide by scale factor
- PDF → Canvas: multiply by scale factor
